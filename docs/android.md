# Slay on Android

Everything the iOS app does has an Android counterpart now, except where
Apple and Google expose genuinely different APIs (noted below). This page is
the map: how to build and run, which permission each feature needs, and
where the code lives.

## Build and run

```sh
export JAVA_HOME=/Library/Java/JavaVirtualMachines/zulu-17.jdk/Contents/Home
export ANDROID_HOME=$HOME/Library/Android/sdk
source ~/.nvm/nvm.sh && nvm use 24

# Emulator (Pixel 7, API 35, Health Connect built in)
$ANDROID_HOME/emulator/emulator -avd slay &

# Release APK (bundles JS, no Metro needed)
cd android && ./gradlew :app:assembleRelease
$ANDROID_HOME/platform-tools/adb install -r app/build/outputs/apk/release/app-release.apk

# Or the dev loop
pnpm start            # Metro
pnpm android          # debug build + install
```

`scripts/gradle-mutex.sh <task>` wraps Gradle in a lock so two sessions
never build the same tree at once. Application id is
`com.lucidbots.lucidapp.adhoc`; Kotlin namespace stays `com.habittracker`.

Maestro flows run on Android with `PLATFORM=android ./e2e/maestro/run-flows.sh <flow>…`
(see `e2e/maestro/README.md` for the iOS-only assumptions still in some flows).

## Feature map

| Feature | iOS | Android | Android permission / setup |
|---|---|---|---|
| Dark mode | DynamicColorIOS tokens | `PlatformColor('@color/…')` tokens backed by `res/values/colors.xml` + `values-night/colors.xml`; the tree remounts (navigation state kept) when the night resources flip; `theme/ThemeManagerModule.kt` persists the choice so cold starts render the right scheme | none |
| Action sheets (Zen, App Lock "Unlocks") | ActionSheetIOS | `src/components/ActionSheet.tsx` bottom sheet, host mounted in App.tsx | none |
| Weather chip + rain alerts | CoreLocation | Same Open-Meteo service; location permissions now declared in the manifest | Location (runtime dialog from the Settings toggle) |
| Steps + sleep | HealthKit | Health Connect (`react-native-health-connect`) in `src/services/health.ts` | READ_STEPS / READ_SLEEP via the Health Connect sheet |
| Zen quiet mode | "Slay Zen" Shortcut sets a Focus | Do Not Disturb (priority filter) via `zen/ZenModeModule.kt`, restored by an alarm at session end | "Do Not Disturb access" (special permission page) |
| Home-screen widgets | WidgetKit streak + lock-screen quote | `widget/StreakWidgetProvider.kt` (2x2, 4x2) and `QuoteWidgetProvider.kt` (4x1, 4x2), fed by the same `sharedState` JSON through `WidgetBridge` | none |
| App Lock | Screen Time / Family Controls (blocked: no provisioning profile) | `applock/`: Usage-access polling foreground service + full-screen overlay shield; picker screen lists launchable apps | Usage access + Display over other apps (special permission pages) |
| Screen Time report | DeviceActivityReport (numbers never reach the app) | `screentime/`: pickups, total and social-app minutes, top apps from UsageStatsManager, shown inline in Activity → Wellbeing | Usage access |
| Backup: survives uninstall | iCloud backup of app data | Android Auto Backup (`res/xml/backup_rules.xml`, `data_extraction_rules.xml`) includes the AsyncStorage database and Slay's shared prefs; restored automatically at reinstall with the same Google account | none |
| Backup: explicit cloud copy | Share sheet export + paste import | Google Drive app-data folder: sign in, Back up now, auto-backup daily when the app leaves the foreground, Restore, first-launch restore prompt (`src/services/driveBackup.ts`) | Google Sign-In web client id — see `docs/android-google-drive-setup.md` |
| Notifications, reminders, recap, dates, bills | UNUserNotificationCenter | Notifee channels; action buttons embedded per notification | POST_NOTIFICATIONS (runtime, Android 13+) |
| Launcher icon + launch screen | Asset catalog + storyboard | Adaptive icon (`mipmap-anydpi-v26`) generated by `scripts/android-icons.sh`; `launch_background` + Android 12 splash attributes | none |

## Where the native code lives

```
android/app/src/main/java/com/habittracker/
  MainApplication.kt   # registers the packages at // @native-packages
  MainActivity.kt      # Health Connect permission delegate
  usage/UsageAccess.kt # shared "Usage access" helper
  theme/               # ThemeManager (persisted night mode)
  zen/                 # Do Not Disturb + end alarm
  widget/              # WidgetBridge + the two widget providers
  applock/             # AppLock module, foreground service, overlay, boot receiver
  screentime/          # ScreenTimeReport module + UsageEvents aggregation
```

All modules are legacy-style `ReactContextBaseJavaModule`s reached through
`NativeModules.<Name>`, the same pattern the iOS bridges use; the New
Architecture interop layer loads them.

## Verified on the emulator (2026-09-10, Pixel 7 / API 35, release APK)

Cold start and launcher icon, four Maestro flows, dark mode (toggle, state
kept, persisted across relaunch), the Zen sheet and Do Not Disturb, the
location dialog, the Health Connect permission sheet, App Lock (permission
flow, picker, shield overlay over Chrome, unlock, service teardown), the
Screen Time row, the streak widget, the Auto Backup uninstall/restore cycle,
a delivered habit reminder with its action button, and the tab regression
sweep. Screenshots of the run live outside the repo (session scratchpad).

## Known gaps
- Android hides every non-system overlay on top of the system Settings app,
  so App Lock cannot shield Settings itself; ordinary apps are shielded.
- A running Zen session keeps the previously picked apps shielded even when
  App Lock is off (by design in `applyAppLock`; may surprise).
- The Home weather chip needs a network-provider location fix; the emulator
  only feeds GPS, so the chip stays hidden there. Real devices are fine.

- App Lock on Android is a polling service plus an overlay, not an OS
  feature: a determined user can stop the service from system Settings.
  Google Play restricts overlay and usage-access apps, so this is fine for a
  personal sideloaded build and would need policy review for a store listing.
- Zen's end alarm is inexact on Android 12+ (no `SCHEDULE_EXACT_ALARM`);
  the in-app timer and a launch-time self-heal cover the gap.
- Widgets follow the system dark mode, not the in-app toggle (the launcher
  inflates them).
- Notification triggers use WorkManager, so a reminder can slip a few
  minutes under Doze.
