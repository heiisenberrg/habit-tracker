## Vision

### 10x Check
The 2026 market splits habit trackers (Streaks, Habitica) from app blockers
(Opal, One Sec): trackers ignore phone use, blockers ignore habits. Routiner's
habit-gated Screen Time shield — finish Meditate to unlock Instagram — is the
bridge the category lacks, and it already works. The 10x version makes that
loop unmissable at every surface: the block screen itself coaches ("12/30 min
to unlock"), the evening nudge arrives while the day is still winnable, one
chat line logs a habit, and the streak survives a sick day. Everything else
(sync, TestFlight) is plumbing an audience of one doesn't need yet.

## Accepted Scope (added to this plan)

### Ordering constraint (reviewer C6/C9)
1. Migration hardening (v3) lands FIRST — every persisted field added by this
   plan rides that migration. 2. Day rollover (3A). 3. 1A consolidated payload
   BEFORE the D8 shield extension (the shield copy reads it; until then the
   generic fallback is the accepted interim). 4. Other features in any order.
5. The device Release build lands LAST, after the shield extension changes the
   Xcode project (otherwise it builds twice).

### Baseline (plan B)
- Land the work: DONE — pushed to git@github.com:heiisenberrg/habit-tracker.git
  as 9 sliced commits during this review.
- **Store migration hardening (reviewer C9):** bump persist `version` to 3 with
  real per-version `migrate` steps. v2→v3 adds every persisted field this plan
  introduces: `streakFreezes {available, usedOn, runLength}`, `lastRolledDay`,
  `historyReconciled` (recap carries NO prefs — it is fully automatic).
  `migrate` must never return `initial()`. On rehydrate parse failure, a small
  persist-storage wrapper captures the raw string and writes it to a
  timestamped App Group file BEFORE falling back, so data is recoverable.
  Backup import runs old files through these same migrate steps (a v2 backup
  imports into a v3 app losslessly). Fixture test: a frozen v2 JSON snapshot
  must migrate to v3 with zero data loss (deep-equal on every v2 field; new
  v3 fields equal their documented defaults).
- **Day rollover (3A — P1 prerequisite, reviewer C1):** on first store access of
  a new day (app open or background fetch), iterate EVERY elapsed day since
  `lastRolledDay` (capped at 83, the histories window size): write that day's
  real completion fractions
  into `histories` (zero-days for days with no data), shift the window one day
  per iteration, and apply freeze consumption per elapsed day (D6 rules). The
  `vacationMode` flag is evaluated as currently set for all elapsed days —
  stated simplification. One-time reconciliation (guarded by
  `historyReconciled`) replaces synthetic tail days with real data from the
  `completions` map where it exists; reconciled history seeds freeze
  `runLength` at 0 (no retroactive accrual of any kind). Unit-tested with
  clock fixtures incl. the 7-days-offline case; affects dayStreak,
  perfectDayCount, karma, widget dots, Activity heatmap.
- **Backup & restore (4A revised by 8A):** on app-background, the full
  versioned store export is mirrored to a second AsyncStorage key (pure JS —
  both platforms); the corrupt-rehydrate dump goes to another AsyncStorage key
  the same way (parse failure ≠ storage failure, so no native write needed).
  Settings gains Export (share sheet — the only true off-device durability)
  and Import (validate version → run the same migrate steps → confirm gate →
  pre-import safety snapshot → replace store). Round-trip unit test:
  export → import → deep-equal.
- **Single-writer rule (OV1, outside voice):** every mutation — notification
  actions, background rollover, imports — goes through the zustand store API
  after awaiting hydration (`persist.onFinishHydration`); NO code path writes
  the `routiner-store` key directly. Headless contexts import the store,
  await hydration, call actions. Day rollover is triggered by three explicit
  hooks: store hydration completion, AppState → active, and a foreground
  midnight timer (the 23:55-crossing case).
- **Streak counter (OV2, outside voice):** rollover maintains persisted
  `streak { current, best }`; a rolled perfect day increments, a missed day
  consumes a freeze or resets, vacation days no-op (evaluated with the flag as
  currently set — stated simplification). `dayStreak` reads the counter (no
  84-day cap); `histories` stays pure chart data. Fraction semantics: histories
  hold 0..1 fractions and EVERY consumer thresholds at >= 1 for "done" —
  including `habitStreak` (currently truthy-buggy on fractions), `totalOf`,
  `rate30`, HabitDetail and Profile screens.
- **Notification "Mark as done" actions (reviewer C4 + OV):** per-habit
  notification categories, re-registered whenever habits change, with existing
  triggers rescheduled to carry their categoryId. Check habits: one "Mark done"
  action. Count habits: two actions — "+step" (e.g. "+500 ML") and "Complete".
  Handler follows the single-writer rule (OV1), then re-evaluates App Lock +
  shared payload.
- **Seed honesty (10A):** `initial()` seeds EMPTY completions (a fresh or
  reset store must never satisfy App Lock — Reset re-evaluates the shield
  immediately); one-time reconciliation ZEROES pre-install synthetic days;
  the streak counter starts from the user's real consecutive run. One-time
  in-app note explains the honest streak drop after upgrade.
- Widget avatar asset swap (needs user-supplied image file); scrub leftover
  social demo copy — known surfaces: `src/data/profileFeed.ts` feed strings,
  Notifications seed items ("Your friends miss you"), `src/data/seed.ts`
  friends fixtures (reviewer C10).

### Expansions (accepted this review)
- **Streak freeze (D6) — rules (reviewer C3):** accrue 1 freeze per 7
  *consecutive* perfect days, counter resets on an imperfect day; cap 2 held.
  Consumption happens at day rollover: each missed day consumes exactly one
  freeze if available, else the streak resets (2 missed days with 1 freeze =
  reset). Vacation-mode days neither break the streak nor consume freezes nor
  count toward accrual. No retroactive accrual from synthetic history. State
  `streakFreezes: { available: number; usedOn: string[]; runLength: number }`
  rides the v3 migration.
- **Assistant quick-log (D7, reviewer C5):** a NEW intent parser (not
  parseQuickAdd, which only parses creation syntax) — fuzzy habit-name match +
  quantity/unit parse for phrases like "done meditate" / "500 ml" /
  "log 20 min reading". Ambiguity → the flow asks "which habit?" with chips;
  no match → offers to create. Effort honestly S-M because the parser is new.
- **Shield screen (D8) — implementation notes (reviewer C8 + OV3):** STEP ONE
  is a provisioning spike — create the Managed Settings UI extension target
  (xcodeproj-ruby recipe) with `com.apple.developer.family-controls` on its
  new bundle id and verify the borrowed team (QAW658347B) mints a profile;
  refusal auto-defers D8 to TODOS with no sunk feature work. iOS 16 minimum
  stated. Then: `ShieldConfiguration` data source joins App Group
  `group.com.lucidbots.lucidbots`; UI limited to title/subtitle/icon/buttons;
  refreshes when re-presented, NOT live. The app mirrors unlock-habit name +
  progress into the consolidated `sharedState` payload (1A) on every
  completion write. Missing/corrupt payload → generic fallback copy, never a
  crash.
- **Evening recap (D9) — trigger lifecycle (reviewer C7):** a ONE-SHOT 21:00
  Notifee trigger (not repeating — a repeating trigger would fire stale
  summaries on days the app never runs; a missed recap is the deliberately
  chosen failure mode). Recomputed and rescheduled for the next 21:00 on every
  completion change while the app runs and by the existing background-fetch
  path; cancelled when the day turns perfect, when a Zen session covers 21:00,
  or when vacation mode is on; re-armed at next evaluation. Suppression = the
  trigger simply isn't scheduled. No user-facing preferences in v1.

### Architecture decisions (this review)
- **1A:** one consolidated App Group `sharedState` JSON (streak, week marks,
  lock state, unlock habit, progress, backup metadata) written by a single
  bridge call; widget Swift decode migrates to the new shape in the same change.
- **2A (extended by 9C):** HomeScreen splits into HeroBanner, ZenControls,
  TasksSection, HabitsSection; AssistantScreen (the file actually gaining
  features) splits into ChatTranscript, FlowInput, MenuCards. Mechanical
  refactors, screenshot-verified, no behavior change.
